# SPATIA 프로젝트 종합 계획서 및 사용 안내서

프로젝트명: SPATIA (스페이시아)  
부제: 건축물의 구조와 공간 연결을 활용한 점검 지원 및 유지관리 역할 체험 플랫폼  
핵심 기술: GIS · BIM · 3D 시각화 · 공간 관계 분석 · Firebase Authentication  
기준일: 2026년 11월 2일  
대상: 현재 로컬 수정본. 최근 변경 사항은 운영 사이트에 배포하지 않은 상태이다.

## 1. 프로젝트 개요

### 1.1 프로젝트 소개

SPATIA는 Spatial(공간)과 Intelligence(지능)를 결합한 이름이다. 건물의 벽·바닥·천장·기둥·보·배관을 고유한 구조물 ID로 구분하고, 위치·자재·결함 이력과 주변 구조물의 연결 관계를 살펴보는 웹 기반 연구용 데모이다.

사용자는 건물 모델에서 구조물을 선택하고, 인접·교차·상하층·배관 연결을 근거로 함께 살펴볼 점검 후보를 찾을 수 있다. 시공·자재·결함·환경 지표를 합산한 점검 우선순위도 비교할 수 있다.

유지관리 과정은 입주자·관리자·전문가 역할을 바꾸며 같은 브라우저에서 체험한다. 로그인한 여러 사용자가 서버 기록을 공유하는 공동 관리 서비스는 현재 제공하지 않는다.

### 1.3 핵심 목표

1. 구조물의 위치와 속성을 같은 ID로 연결한다.
2. 로컬 건물 좌표와 지도 좌표를 명시적인 기준으로 연결한다.
3. 주변 구조물과 배관 연결을 이용해 점검 후보를 탐색한다.
4. 점검 순서를 수치와 분석 근거로 비교한다.
5. 신고·담당자 배정·점검 기록·설명 검토·보수 확인을 역할별로 체험한다.
6. 실제 사례를 확보했을 때 분석 방법을 비교할 수 있는 연구 도구를 제공한다.

## 2. 기획 배경과 해결 방향

건축물의 자재·시공·점검 자료가 분리되어 있으면, 특정 위치의 문제와 주변 구조물의 관계를 함께 확인하기 어렵다. 천장의 누수 흔적을 살펴볼 때도 해당 천장뿐 아니라 상층 구조물과 인접 배관을 함께 점검할 필요가 있다.

SPATIA는 구조물 ID를 기준으로 정보를 연결하고, 공간 관계를 점검 후보를 찾는 단서로 사용한다. 전문가용 원문과 입주자용 쉬운 설명을 구분하는 유지관리 흐름도 시연한다.

공간적으로 가깝거나 연결되어 있다는 이유만으로 같은 결함이 발생했거나 결함이 전파되었다고 판단하지 않는다. 실제 원인과 안전성은 현장 조사와 전문가 검토로 확인해야 한다.

## 3. 화면과 기능 구성

### 3.1 랜딩 페이지

랜딩은 건물 모션, 메인 문구, 공간 분석 진입 버튼을 중심으로 구성한다. 아래로 스크롤하면 가상 건물을 회전해 살펴보고 내부로 접근하는 모션이 나타난다. 시스템의 동작 줄이기 설정에서는 정적인 표현을 사용한다.

랜딩 안에 분석 대시보드를 이어 붙이지 않고, 버튼을 통해 별도 기능 화면으로 이동한다. 홍보용 추가 섹션과 중복 설명은 현재 화면에서 제외했다.

### 3.2 공간 분석의 다섯 메뉴

| 메뉴 이름 | 역할 |
| --- | --- |
| 구조와 위치 확인 | 구조물 위치, 2D·3D 형상, 층과 선택 상태 확인 |
| 선택한 구조물과 주변 구조물의 연결 | 교차·인접·상하층·배관 연결 후보와 관계 설정 확인 |
| 점검 우선순위 | 구조물별 Q·M·D·E와 종합 점수 비교 |
| 결함 분포·시계열 | 층·자재·방향별 분포와 시점에 따른 결함 이력 확인 |
| 분석 비교·연구 검증 | 공간 관계 탐색과 단순 거리 탐색을 기준 집합·사례 자료와 비교 |

이전 메뉴 이름인 ‘Geo-BIM 디지털 트윈’은 ‘구조와 위치 확인’으로, ‘공간 관계 분석’은 ‘선택한 구조물과 주변 구조물의 연결’로 변경했다.

외부 환경 시나리오 메뉴와 강우·일사 조정 화면은 삭제했다. 분석에 사용하는 환경 지표 E 자체는 남아 있다.

### 3.3 GIS 입지

건물의 로컬 좌표와 지도의 투영좌표를 연결한다. 사용자가 좌표계·원점·회전·축척·높이·출처를 입력하면 변환된 건물 경계를 지도에서 확인할 수 있다.

출처 정보를 입력한 외부 Polygon·MultiPolygon GeoJSON을 읽어 건물과 경계상자가 겹치는 후보를 확인할 수 있다. 좌표 변환 상세 설명은 접어서 볼 수 있다.

### 3.4 역할 체험

| 역할 | 주요 체험 |
| --- | --- |
| 입주자 | 구조물 선택, 관리 요청, 공개된 설명 확인, 보수 결과 확인·재요청 |
| 관리자 | 요청 조회, 담당자·일정·처리 단계 변경, 설명 공개 승인 |
| 전문가 | 요청 조회, 자재·시공 기록 확인, 점검 원문과 쉬운 설명 작성·검토 |

구조물 맵은 입체·평면 전환과 좌우 회전을 지원한다. 선택한 구조물 강조, 진행 중 요청 표시, 같은 구조물의 공간 분석 화면 연결도 제공한다.

역할 버튼은 체험용 화면 전환이다. 실제 직무 인증이나 서버 권한 부여가 아니며, 로그인 계정의 역할과 연동되지 않는다. 기록은 같은 브라우저에서 이어서 사용하는 데모 자료이다.

### 3.5 로그인과 사용 가이드

로그인은 별도 페이지에서 제공한다. 이메일과 비밀번호로 계정을 만들고 로그인·로그아웃할 수 있다. 로그인 상태에 따라 상단 링크는 ‘로그인’ 또는 ‘내 워크스페이스’로 표시된다. 현재 ‘내 워크스페이스’는 역할 체험 화면으로 이동한다.

로그인했다고 로컬 모델과 관리 기록이 Firebase에 업로드되거나 계정별로 분리되는 것은 아니다. 사용 가이드는 하단 링크에서 확인할 수 있다.

## 4. 공간정보와 데이터 구성

### 4.1 기본 가상 모델

기본 모델은 4개 층·12세대·84개 구조물이다. 벽체·바닥·천장·기둥·보·배관을 포함한다. 구조물에는 ID, 유형, 층, 세대, 로컬 XYZ 범위, 자재, 시공·검사 날짜, 지표와 출처 등의 속성이 연결된다.

창호·문·발코니·가구 등 추가 시각 표현은 가상 기본 모델에 적용한 표시용 세부이다. 이러한 표현을 실제 시공 도면이나 측정된 BIM 형상으로 해석하지 않는다. 표시용 세부를 추가해도 원래 분석 구조물의 ID와 경계상자는 유지한다.

### 4.2 공개 IFC 변환 샘플

프로젝트에는 공개 Duplex IFC에서 변환한 연구용 JSON이 포함되어 있다.

| 항목 | 샘플 구성 |
| --- | --- |
| 구조물 | 50개 |
| 메시를 포함한 구조물 | 50개 |
| 연결 관계 | 21쌍 |
| 결함 이력 | 가상 기록 25건 |

IFC 객체 식별자, 층·자재 관계, 삼각형 메시와 경계상자를 활용한다. 이 샘플의 가상 결함과 검사 지표는 실제 건물의 점검 결과가 아니다. 샘플 파일은 프로젝트의 `dist/duplex-spatial-model.json`에 있으며 직접 주소로도 열 수 있다.

### 4.3 직접 IFC 가져오기 제한

직접 IFC STEP 읽기는 지원되는 벽·바닥·기둥·보·배관·마감 객체의 단순 사각형·원형 압출을 중심으로 처리한다. 복잡한 BREP·CSG·매핑 형상·임의 단면은 모두 처리하지 못하며, 제외된 항목은 가져오기 검사에서 확인해야 한다.

직접 IFC 읽기와 사전에 변환한 Duplex JSON은 서로 다른 처리 경로이다. 직접 읽기에서는 자재·검사·배관 연결을 자동으로 완전 추출하지 않으며 층도 제한적인 방식으로 추정한다. 따라서 정밀한 IFC 해석이 완료된 범용 BIM 뷰어로 설명하지 않는다.

이전에 제공했던 ‘IFC 메시 우선 표시’ 선택지는 현재 없다. 모델에 포함된 형상정보에 따라 표시되며 해당 선택지를 전환하는 사용 절차도 적용하지 않는다.

### 4.4 ID와 저장 구조

원본 공간 모델의 `buildingId`, 구조물의 `id`, `floor`, `unit`을 중심으로 자료를 연결한다. 유지관리 기록에는 대응되는 건물·층·세대·구조물 식별자를 연결하며, IFC 원본 ID는 제공된 자료에 있는 경우 유지한다.

모든 식별자·자재·검사 정보가 IFC나 외부 기관에서 자동 확인되는 것은 아니다. 기본 모델과 예시 기록에는 연구용 가정이 포함된다.

건물을 바꾸면 이전 건물의 역할 체험 기록을 분리해 보존하는 로직이 있으며, 현재 모델에서 찾을 수 없는 구조물 연결은 미연결로 관리한다. 브라우저 저장소를 삭제하거나 다른 기기·브라우저를 사용하면 같은 로컬 기록이 자동으로 나타나지 않는다.

## 5. 분석 방법

### 5.1 구조물 사이의 관계

| 분석 | 현재 계산 방법 |
| --- | --- |
| 교차 | 세 축에서 축 정렬 경계상자(AABB)의 중첩 확인 |
| 인접 | 경계상자 사이의 최소 유클리드 거리 |
| 상하층 | XY 범위 중첩, 한 층 차이, 수직 간격 조건 |
| 배관 연결 | 모델에 명시된 연결 그래프 탐색 |
| 결함 분포 | 층·자재·방향별 결함 집계 |

기본 인접 거리 기준은 0.35m이고, 배관 탐색은 기본 1단계이며 화면에서 최대 3단계까지 설정할 수 있다. IFC 메시를 표시하더라도 공간 관계 계산은 AABB를 기준으로 한다. 배관의 물 흐름이나 물리적인 결함 전파를 예측하는 모델은 아니다.

### 5.2 GIS 좌표 변환

지원 좌표계는 EPSG:3857과 EPSG:5186이다. 원점 Easting·Northing, 반시계 회전각, 축척, 기준 높이를 사용한다.

```text
E = E₀ + s(x cosθ − y sinθ)
N = N₀ + s(x sinθ + y cosθ)
H = H₀ + sz
```

변환한 건물 경계는 OpenStreetMap 기반 지도에서 확인하고 WGS84 GeoJSON으로 내보낼 수 있다. EPSG:3857에는 거리 왜곡이 있으며, 직접 입력한 좌표를 검증된 현장 위치로 간주하지 않는다. 수직 기준과 실측 잔차도 별도 검증이 필요하다.

외부 GeoJSON 중첩 결과는 경계상자 기반 후보이다. 정밀한 폴리곤 교차나 침수 안전 판정이 아니며, 연결한 외부 자료가 점검 점수를 자동 변경하지 않는다. 기상·DEM·침수 API는 자동 연결하지 않는다.

### 5.3 점검 우선도

기본 가중치는 다음과 같다. 사용자가 바꾼 가중치는 합으로 정규화하여 적용한다.

```text
P = 0.30Q + 0.25M + 0.25D + 0.20E
```

| 지표 | 의미 | 기본 가중치 |
| --- | --- | --- |
| Q | 검사 이상 등 시공 관련 입력 지표 | 30% |
| M | 자재 불일치 관련 입력 지표 | 25% |
| D | 직접·인접 결함과 미완료 요청 | 25% |
| E | 기본 환경 노출 및 코드에 남아 있는 환경 가정 | 20% |

```text
D = min(100, 직접 활성 결함 수 × 38
             + 인접 활성 결함 수 × 12
             + 미완료 요청 수 × 20)
```

환경 시나리오 화면은 삭제했지만 계산 코드에는 강우 30, 일사 50의 기본 가정값이 남아 있다. 현행 계산은 외벽에 강우×0.35와 일사×0.10을, 1층 바닥에 강우×0.20을 기본 E에 더한 뒤 0~100으로 제한한다. 이 값은 현재 사용자 조정 메뉴나 실제 관측값을 뜻하지 않는다.

| 점수 | 분류 |
| --- | --- |
| 35점 미만 | 정기 점검 |
| 35점 이상 60점 미만 | 관찰 |
| 60점 이상 | 우선 검토 |

점수는 검토 순서이며 붕괴 확률·법적 안전 등급·결함 원인 확정 결과가 아니다. 예시 점수는 가중치, 분석 시점, 모델 및 로컬 요청 기록에 따라 달라질 수 있다.

### 5.4 비교와 검증

선택한 구조물의 공간 관계 기반 후보와 중심점 거리 기반 후보를 기준 집합에 대조해 TP·FP·FN, Precision·Recall을 계산한다. 화면의 기본 기준 집합은 시연용 가정이다.

사례 JSON을 읽을 때는 건물 ID, 자료 유형, 출처, 검토자·검토일, 기준 구조물, 평가한 구조물, 실제 확인한 구조물을 명시한다. 평가 범위 밖의 후보는 별도로 집계하며, 기준 자료가 실제 현장 자료인지 사이트가 독립적으로 인증하지는 않는다.

현재 실제 현장 정답을 확보해 분석 성능을 검증했다고 주장할 수 없다. 기능 구현과 현장 타당성 검증은 구분한다.

## 6. 현재 제공 범위와 제한

### 6.1 현재 제공하는 기능

- 건물 2D·3D 표시, 회전·확대·층 필터·층 분리·구조물 선택
- 사각형 영역 선택과 선택 구조물 목록
- 공간 관계와 배관 연결 후보 탐색
- 점검 우선순위·가중치 비교·결함 분포·분석 시점 필터
- 기준 집합 및 사례 JSON을 사용한 분석 방법 비교
- 지원 형식의 모델 가져오기, 모델·분석 JSON 및 우선순위 CSV 내보내기
- GIS 기준점 저장, 지도 표시, 외부 GeoJSON 후보 확인·경계 내보내기
- 같은 브라우저에서 요청·점검·설명 검토·보수 확인을 진행하는 역할 체험
- 독립된 Firebase 계정 가입·로그인·로그아웃

### 6.2 화면에서 제거하거나 축소한 기능

| 항목 | 현재 상태 |

| 개인 클라우드 백업·복원 | 페이지와 사용자용 진입 제거 |

### 6.3 인증과 정보 공개의 한계

Firebase 인증은 현재 계정 상태 확인에 사용한다. 역할 체험의 역할·세대 필터와 설명 공개 승인은 브라우저 데모 로직이며, 실제 비공개 업무자료의 보안 경계가 아니다. 전문 기록도 로컬 자료에 포함될 수 있으므로 민감한 실제 개인정보나 비공개 현장 기록을 운영 서비스처럼 저장하지 않는다.

공동 관리와 개인 백업 페이지 삭제는 현재 웹 기능에서 제외했다는 의미이다. Firebase 서버의 기존 데이터·규칙이 모두 삭제되었다는 의미는 아니다.

## 7. 사용 방법

### 7.1 접속 주소

현재 수정본 확인용 주소는 다음과 같다. 로컬 미리보기 서버가 실행 중인 컴퓨터에서 사용한다.

| 화면 | 로컬 주소 |
| --- | --- |
| 홈 | http://127.0.0.1:4173/ |
| 공간 분석 | http://127.0.0.1:4173/workspace.html |
| GIS 입지 | http://127.0.0.1:4173/gis.html |
| 역할 체험 | http://127.0.0.1:4173/management.html |
| 로그인 | http://127.0.0.1:4173/login.html |
| 사용 가이드 | http://127.0.0.1:4173/guide.html |

기존 운영 주소는 `https://roaring-maamoul-d1bbf1.netlify.app/`이지만, 이 문서가 설명하는 최신 로컬 변경 사항이 모두 반영된 운영 주소로 안내하지 않는다.

### 7.2 구조와 위치 확인

1. 홈에서 ‘공간 분석 바로 시작’을 누른다.
2. ‘구조와 위치 확인’을 선택한다.
3. 모델을 드래그해 회전하고 휠 또는 확대·축소 버튼을 사용한다.
4. 층 버튼으로 표시 범위를 바꾸고, 필요하면 층 분리 보기를 사용한다.
5. 구조물을 클릭하거나 ‘분석 구조물 선택’ 목록에서 대상을 고른다.
6. 2D·3D와 색상 레이어를 전환하며 위치와 선택 상태를 확인한다.

오른쪽 분석 메뉴는 접거나 펼칠 수 있다. 모바일에서는 ‘분석 메뉴’ 버튼으로 연다.

### 7.3 모델 가져오기

1. 현재 모델을 보존하려면 ‘분석 결과 내보내기’에서 모델 JSON을 내려받는다.
2. ‘모델 가져오기’를 누른다.
3. 지원되는 JSON 또는 IFC 파일을 선택한다.
4. ‘파일 읽기·검사’를 실행하고 구조물 수·경고·제외 항목을 확인한다.
5. ‘검사한 모델로 교체’를 누른다.
6. 새 모델의 층·구조물 목록·형상을 확인한다.

현재 입력 제한은 파일 8MB 이하, 구조물 500개 이하이다. 파일은 브라우저에서 읽는다. Duplex 샘플은 `http://127.0.0.1:4173/duplex-spatial-model.json`에서 확보해 같은 절차로 읽을 수 있다. 사용 가이드에 다운로드 버튼이 있다고 전제하지 않는다.

### 7.4 주변 구조물 연결 확인

1. 대상 구조물을 선택한다.
2. ‘선택한 구조물과 주변 구조물의 연결’을 연다.
3. 인접 거리와 배관 탐색 단계를 설정한다.
4. 교차·인접·위층·아래층·배관 연결 등의 후보와 근거를 확인한다.
5. 후보 구조물을 선택해 위치를 살펴본다.

연결된 후보는 추가 점검의 단서이지 결함이 확인된 구조물 목록이 아니다.

### 7.5 점검 우선순위와 결함 분포

1. ‘점검 우선순위’에서 구조물별 지표와 점수를 확인한다.
2. 구조물 유형·최소 점수로 목록을 좁힌다.
3. 필요한 경우 가중치를 바꿔 결과 차이를 비교한다.
4. ‘결함 분포·시계열’에서 집계 기준과 분석 시점을 바꾼다.
5. 내보내기에서 분석 근거 JSON 또는 우선순위 CSV를 저장한다.

시점 필터는 결함 발생·종료일과 요청 등록일을 반영하지만, 모든 지표와 요청 상태를 과거 이력으로 완전히 재구성하지는 않는다.

### 7.6 GIS 위치 연결

1. ‘GIS 입지’를 연다.
2. EPSG:3857 또는 EPSG:5186을 선택한다.
3. 원점 Easting·Northing을 입력한다. 필요하면 경위도 원점을 변환한다.
4. 회전각·축척·높이·좌표 기준 출처를 입력한다.
5. ‘좌표 기준 저장·지도 표시’를 실행한다.
6. 지도에 표시한 건물 경계를 확인하고 필요하면 GeoJSON으로 내보낸다.
7. 외부 자료를 비교하려면 출처·기준일을 적고 지원 형식 GeoJSON을 읽는다.

좌표 기준은 로컬 모델과 모델 JSON에 반영한다. 외부 GeoJSON은 해당 페이지 메모리에 유지하며 자동 클라우드 백업하지 않는다.

### 7.7 역할 체험

1. ‘역할 체험’에서 입주자·관리자·전문가를 선택한다.
2. 입주자는 구조물과 불편 사항을 선택해 새로운 관리 요청을 등록한다.
3. 관리자는 요청에서 담당자·예정일·처리 단계를 입력한다.
4. 전문가는 연결할 요청·구조물을 선택하고 점검 원문과 쉬운 설명을 작성한다.
5. 필요하면 용어 사전으로 초안을 채운 뒤 직접 검토한다. 생성형 AI는 사용하지 않는다.
6. 관리자는 검토된 설명의 공개를 승인한다.
7. 입주자는 공개된 설명과 처리 상황을 확인한다.
8. 보수 완료 후 확인·만족도 또는 미해결 재요청을 체험한다.

이 절차는 같은 브라우저에서 역할을 전환해 진행한다. 실제 계정별 공유, 전문가 UID 배정, 서버 실시간 동기화를 안내하지 않는다. 역할 체험의 제한된 사진 첨부는 브라우저 저장용이며 서버 사진 업로드가 아니다.

### 7.8 분석 검증

1. ‘분석 비교·연구 검증’을 연다.
2. 합성 기준 집합으로 두 탐색 방법의 차이를 확인한다.
3. 별도 사례가 있다면 화면에서 사례 JSON 양식을 내려받는다.
4. 건물 ID·출처·검토자·검토일과 평가 대상·확인 구조물을 작성한다.
5. 자료를 읽어 Precision·Recall과 평가 범위를 확인한다.
6. 결과 JSON을 내보낸다.

가상 사례는 합성 자료로 표시한다. 독립적인 현장 점검 자료가 없는 결과를 실제 성능으로 발표하지 않는다.

### 7.9 가입·로그인·로그아웃

1. 상단 ‘로그인’을 연다.
2. 이메일과 비밀번호를 입력한다.
3. 처음 사용하면 ‘계정 만들기’, 기존 계정이면 ‘로그인’을 누른다.
4. 로그인 상태를 확인한다.
5. 로그아웃하려면 하단 ‘계정’ 링크로 로그인 화면을 열어 ‘로그아웃’을 누른다.

계정 인증은 모델 저장·역할 권한·관리 기록 공유를 자동으로 활성화하지 않는다. 비밀번호는 사용자 본인이 입력한다.

## 8. 활용 시나리오

302호 천장에서 누수 흔적을 발견했다고 가정한다.

1. 입주자 체험에서 관련 구조물을 골라 요청을 등록한다.
2. 같은 구조물의 공간 분석 화면으로 이동한다.
3. 주변 구조물·상하층·배관 연결 후보를 확인한다.
4. 점검 우선순위와 연결된 결함 이력을 비교한다.
5. 관리자 역할에서 담당자와 점검 일정을 기록한다.
6. 전문가 역할에서 점검 원문·쉬운 설명을 작성하고 검토한다.
7. 관리자 역할에서 설명 공개를 승인한다.
8. 입주자 역할로 돌아가 설명을 읽고 보수 결과 확인을 체험한다.

이 시나리오는 업무 흐름을 설명하는 로컬 데모이다. 실제 누수 원인 진단이나 원격 관리사무소 접수 완료를 의미하지 않는다.

## 9. 검증 현황과 한계

현재 수정 과정에서는 공간 분석 화면 렌더링, 구조물 선택, 모델·관계·점수 데이터 보존, 역할별 조회·검토 로직, GIS 좌표 계산, 사례 비교, 페이지 분리와 스크롤 모션 등을 로컬 검사와 화면 점검으로 확인했다.

이전 문서의 공동 관리·백업 관련 운영 검사 횟수를 현재 제공하는 기능의 검증 실적으로 그대로 사용하지 않는다. 로그인 화면과 인증 연결의 구현 여부, 실제 계정으로 로그인해 확인한 결과, 서버 보안 검증, 현장 분석 성능은 각각 구분해야 한다.

현재의 주요 한계는 다음과 같다.

- 실제 BIM-GIS 측량 정합과 현장 위치 정확도 미검증
- 정밀 메시 교차 대신 AABB 관계 계산 사용
- 가상 검사 지표·결함 이력·기준 집합 포함
- 실제 현장 정답 자료로 분석 성능 검증 미완료
- 기상·DEM·침수 API와 실시간 센서 자동 연동 없음
- 생성형 AI·균열 이미지 탐지 모델 연결 없음
- 실제 계정별 유지관리 협업·직무 권한·전문가 자격 검증 제공 안 함
- 완전한 변경 감사 로그·전자서명·서버 알림 발송 제공 안 함
- 브라우저 저장을 계정별 비공개 업무자료 저장소로 사용할 수 없음

## 10. 향후 개발 및 기대 효과

### 10.1 향후 개발

1. 실제 기준점과 BIM 자료를 확보해 지도 배치 오차·잔차를 검증한다.
2. 실제 구조물 형상과 설비 자료를 이용해 관계 계산을 정밀화한다.
3. 전문가가 검토한 사례로 공간 관계 탐색과 단순 거리 탐색을 비교한다.
4. 환경 지표의 남아 있는 가정값을 정리하고, 검증 가능한 근거로 대체한다.
5. 필요성이 확인되면 출처·기준일·해상도를 갖춘 외부 공간자료 연계를 연구한다.
6. 향후 공동 관리 재도입 시 서버 권한·개인정보·감사·백업·동시 사용을 별도 설계한다.
7. AI 설명 기능은 전문가 검토 절차를 전제로 연구한다.

위 항목은 향후 계획이며 현재 제공하는 서비스로 설명하지 않는다.

### 10.2 기대 효과와 결론

SPATIA는 구조물 ID를 중심으로 위치·속성·결함·점검 요청을 연결하고, 주변 구조물과의 관계를 추가 점검의 근거로 제시한다. 또한 역할 체험을 통해 전문 기록과 쉬운 설명을 구분하는 관리 과정을 이해하도록 돕는다.

현재의 정체성은 **공간정보 기반 점검 지원과 유지관리 업무 흐름을 시연하는 연구용 웹 데모**이다. 실제 현장 자료로 정확성과 효과를 검증한 운영 서비스로 발전시키는 것은 후속 과제이다.
