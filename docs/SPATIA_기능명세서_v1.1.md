# SPATIA 기능명세서

문서 버전 1.1 | 작성일 2026년 10월 31일 | SPATIA 3.0 개선 반영

## 1 서비스 범위와 사용자

Spatial + Intelligence: 건물의 공간 관계를 분석하고 점검 요청·전문가 설명·처리 상태를 연결한다. 기본 공동주택은 가상이며 공개 Duplex IFC 연구용 부분집합을 불러올 수 있다.

| 화면 | 목적 |
| --- | --- |
| 공간 분석 | 객체 선택·관계·우선순위·결함·검증 |
| GIS 입지 | 투영좌표 기준 연결·지도·GeoJSON |
| 역할 체험 | 같은 공간 ID의 브라우저 데모 |
| 공동 관리 | 실제 로그인·멤버십 기반 서버 요청 공유 |
| 개인 백업 | UID별 명시적 스냅샷 저장·복원 |
| 사용 가이드 | 다섯 단계 안내·권한 초기 설정 |

공동 관리의 역할은 서버 멤버십으로 결정한다. 역할 체험 버튼은 실제 계정 권한을 바꾸지 않는다. 공개 사이트 열람에는 Netlify 로그인이 필요하지 않다. Firebase 업무 기록은 별도 인증과 권한이 필요하다.

실제 현장 안전 등급, 결함 원인 확정, 법규 판정과 검증된 AI 예측을 제공하지 않는다. 학교 샘플은 제거했다. 운영 주소는 https://roaring-maamoul-d1bbf1.netlify.app/ 이다.

## 2 통합 건물·층·세대·구조물 식별자

모델은 version=3, crs=LOCAL_METERS, buildingId와 구조물 배열을 가진다. 기본 buildingId는 forest-a-demo, 공개 IFC는 duplex-public-ifc다. 이전 모델의 건물 ID가 없으면 정렬한 구조물 ID를 기반으로 안정적인 식별자를 만든다.

| 항목 | 규약 |
| --- | --- |
| buildingId | 영문·숫자·밑줄·하이픈, 최대 100자 |
| floorId | buildingId-F층번호 |
| unitId | 로컬 연결에서는 건물 ID와 세대 ID를 함께 보존 |
| elementId | 원본 구조물 ID 보존, 슬래시 금지 |
| IFC 연결 | ifcGuid, ifcStorey, 원본 STEP/형상 식별자 |

유지관리 자재 목록은 현재 공간 모델에서 구조물 ID별로 생성한다. 편집은 공간 분석의 속성 화면으로 연결하며 별도의 자재 사본을 편집하지 않는다. 다른 탭의 모델 변경은 열린 폼을 강제 교체하지 않고 안내한다.

건물을 바꾸면 이전 건물의 요청·기록·알림을 archivedBuildings에 보존하고 현재 건물의 자료만 활성화한다. 현재 모델에서 찾을 수 없는 기존 ID는 unresolved로 표시한다. 엘리베이터 등 누락된 형상을 임의로 다른 객체에 연결하지 않는다.

브라우저 데모 자료와 실제 공동 관리 자료는 자동 병합·업로드하지 않는다. 서버의 경로는 buildings/{buildingId} 아래 elements·members·requests·inspections·publicUpdates로 분리된다.

## 3 BIM 객체·형상·자재

공개 Duplex 샘플은 건축·배관 IFC의 객체 50개, 포트 연결 21개, 가상 결함 25건으로 구성된다. IfcOpenShell로 객체의 세계 좌표 삼각형 메시, AABB, IFC GlobalId, 층 컨테이너와 자재 관계를 추출했다. 원본 IFC 출처와 CC BY 4.0 저작자 표시는 NOTICE에 기록한다.

뷰어는 IFC 메시 우선 표시와 분석 경계상자 표시를 전환한다. 2D·3D, 회전·확대, 층 필터와 층 분리, 객체 선택을 지원한다. 메시가 없는 객체는 AABB를 표시한다. 공간 관계 분석은 메시 정밀 교차가 아닌 AABB를 사용한다.

직접 IFC STEP 가져오기는 8MB 이하의 직접 사각형·원형 압출과 LOCALPLACEMENT, 미터·밀리미터를 지원한다. 명시된 IFC 층과 자재 관계를 연결하고 미연결 층은 높이 3.2m 기준으로 추정한다. 복합·매핑·CSG 형상 등은 제외 경고를 표시한다. 직접 IFC 가져오기는 전체 BIM 엔진을 대신하지 않는다.

JSON은 1~500개 객체, 중복 없는 ID, 유효한 XYZ 경계, 결함·연결 참조를 검사한다. 메시별 3,000 꼭짓점·6,000 삼각형, 전체 60,000 삼각형을 제한한다. 인덱스 범위와 경계 밖 꼭짓점도 거부한다.

공개 IFC의 Q/M/E·결함은 가상이며 자재 제조사·실제 시공일·검사 결과를 자동으로 검증하지 않는다. 모델 JSON에는 형상·좌표 기준·수정 이력이 함께 저장된다.

## 4 GIS 위치와 BIM 좌표 연결

GIS 입지 화면에서 EPSG:3857 또는 EPSG:5186, 원점 Easting/Northing, 반시계 회전, 축척, 원점 높이와 출처를 등록한다. 경위도로 원점을 입력하면 proj4로 선택 좌표계에 변환한다.

E = E0 + s(x cos(theta) - y sin(theta))
N = N0 + s(x sin(theta) + y cos(theta))
H = H0 + sz

로컬 공간 분석 좌표는 변경하지 않는다. 지도에는 모델 전체 XY 경계를 변환한 폴리곤을 표시하고 WGS84 GeoJSON으로 내보낸다. 배경 지도는 OpenStreetMap이며 저작자 표시를 유지한다.

Duplex의 IfcSite 기재 경위도는 참고 위치로 제공한다. 이 위치만으로 BIM 원점·진북·수직 기준면 또는 실제 건물과의 정합이 검증되지는 않는다. EPSG:3857은 거리 왜곡이 있으며 내부 거리 분석에 사용하지 않는다. 모든 사용자 입력 좌표 기준은 미검증으로 표시한다.

외부 환경 자료는 출처·기준일을 입력한 WGS84 Polygon/MultiPolygon GeoJSON(2MB, 500개 형상, 50,000개 좌표 이하)을 연결한다. 건물과 자료의 경계상자 중첩 후보를 표시한다. 정밀 폴리곤 교차·침수 판정이 아니며 자동으로 Q/M/D/E를 변경하지 않는다.

기상·DEM·침수 API와 실시간 센서는 연결하지 않았다. 현장 적용 전 실측 기준점과 공공 자료의 좌표계·기준일·정확도를 검증해야 한다.

## 5 공간 관계와 점검 우선순위

세 축 AABB 중첩으로 교차를 계산하고 경계 간 유클리드 거리로 인접을 계산한다. 기본 인접 거리는 0.35m다. XY가 겹치고 층 차가 1이며 수직 간격이 허용 범위인 구조물을 상하층 후보로 표시한다. 배관은 명시된 연결 그래프를 0~3단계 탐색한다.

P = 0.30Q + 0.25M + 0.25D + 0.20E

D = min(100, 직접 활성 결함*38 + 인접 활성 결함*12 + 미완료 요청*20)

환경 E에는 가정한 강우·일사 강도를 적용하며 0~100으로 제한한다. 외벽은 기본 E + 강우*0.35 + 일사*0.10, 1층 바닥은 기본 E + 강우*0.20이다. 시나리오 값은 실제 mm·관측값이 아니다.

| 점수 | 의미 |
| --- | --- |
| 35 미만 | 정기 점검 후보 |
| 35 이상 60 미만 | 관찰 필요 |
| 60 이상 | 우선 검토 |

가중치는 합으로 정규화하고 모두 0이면 거부한다. 결함 분포는 층·자재·방향별 집계이며 통계적 핫스폿 검정이 아니다. 이력 시점은 결함 발생·종료와 요청 등록일에 적용한다. 현재 처리 상태를 과거 상태로 재구성하지는 않는다.

이 점수는 점검 순서용 연구 지표다. 구조 안전 등급·고장 확률·누수 전파의 물리적 증거가 아니다. 원인과 실제 개선 효과는 현장에서 검증한다.

## 6 출처가 있는 사례 비교 검증

기존 합성 기준의 탐색 비교와 사용자 제공 사례 검증을 구분한다. 사례 JSON은 같은 buildingId, referenceType(field/expert/synthetic), source, reviewer, reviewedAt과 1~100개 cases가 필요하다.

각 사례는 중복 없는 caseId, anchorId, evaluatedIds, confirmedIds를 가진다. 검토 범위에 존재하는 객체만 허용하고 확인된 결함은 검토 범위의 부분집합이어야 한다. 기준 구조물 자체와 알 수 없는 ID, 중복 사례를 거부한다.

공간 관계+배관 후보와 단순 중심점 거리 후보를 같은 검토 범위에 제한해 비교한다. 미검토 예측은 별도로 세며 정상으로 간주하지 않는다. 사례별 TP/FP/FN과 전체 micro Precision/Recall을 내보낸다. 분모가 0인 집계는 계산 불가로 표시한다.

Precision = TP / (TP + FP)
Recall = TP / (TP + FN)

파일에는 출처·검토자·기준일·사례별 결과·반경·관계 설정을 포함한다. 출처 정보는 업로드 사용자의 선언이며 SPATIA가 기록의 진위·대표성·평가 독립성을 인증하지 않는다.

현재 실제 현장 정답 집합은 확보되지 않았다. 양식은 synthetic으로 제공한다. 실제 또는 독립 전문가가 검토한 사례, 비교 설계와 충분한 표본을 확보한 뒤에만 연구 성능으로 보고해야 한다.

## 7 인증과 공동 관리 요청

Firebase Authentication 이메일/비밀번호 로그인과 Firestore 서버 보안 규칙을 사용한다. 화면의 역할 선택으로 권한을 부여하지 않는다. systemAdmins/{uid} 문서는 프로젝트 소유자가 콘솔에서 최초 등록한다. 이후 시스템 관리자는 건물 멤버십을 등록한다.

| 역할 | 허용 범위 |
| --- | --- |
| 입주자 | 본인 세대/공용부 구조물, 본인 요청, 승인 설명 |
| 관리자 | 담당 건물 요청·기록·공개 승인·구조물 갱신 |
| 전문가 | 배정 요청·작성 점검 원문 |
| 시스템 관리자 | 건물·멤버십·구조물·공개 정책 |

requests는 ownerUid·unitId·elementId·assignedUid·stage·일정·서버 시각을 저장한다. 입주자는 자신의 UID로만 등록한다. 관리자는 전문가 멤버십이 있는 UID에 배정하고 처리 단계를 진행한다. 보수 예정·완료에는 일정이 필요하다. 완료 후 요청한 입주자만 확인 단계로 바꿀 수 있다.

조회는 ownerUid·assignedUid·unitId로 제한하며 조건을 조작한 전체 조회는 서버가 거부한다. onSnapshot으로 다른 계정의 변경을 수신하고 서버 확인본만 갱신한다. 오류 시 로컬 데모 저장으로 대체하지 않는다.

로컬 역할 체험은 별도이며 실제 직무 인증을 대신하지 않는다. 실제 사용자 멤버십은 프로젝트 소유자가 신원을 확인하고 등록해야 한다.

## 8 비공개 원문·공개 승인·개인 백업

inspections에는 담당 전문가의 원문·쉬운 설명·다음 조치·검토 여부·개정을 저장한다. 입주자는 원문 컬렉션을 읽을 수 없다. 관리자는 검토된 설명과 같은 문장·개정만 publicUpdates에 승인할 수 있다. 공개 문서에는 raw를 허용하지 않는다.

공개는 승인 시점의 사본이다. 원문을 수정해도 승인 설명은 자동 변경되지 않는다. 입주자는 본인 세대와 공용부의 공개본만 읽는다. 공개 이력의 완전한 감사 로그나 전자 서명은 아직 제공하지 않는다.

AI 모델은 연결하지 않았다. 로컬 역할 체험의 쉬운 설명 초안은 용어 사전 기반이며 전문가가 직접 수정·검토해야 한다. 실제 전문가 자격 검증·알림 발송·사진 업로드는 향후 범위다.

개인 백업 경로는 users/{uid}/snapshots/model 또는 operations다. 종류별 최신 스냅샷 한 개를 저장하고 서버 성공 후 완료를 표시한다. 800,000 UTF-8 bytes 이하이며 본인 UID만 접근한다. 복원은 형식 검사와 교체 확인 후 수행한다.

개인 관리 백업에는 로컬 데모의 비공개 원문·사진이 포함될 수 있다. 공동 업무 기록을 개인 백업으로 자동 복사하지 않는다. 실제 공동 데이터와 로컬 데이터의 자동 병합·전체 공동 모델 다운로드는 제공하지 않는다.
